# Design handoff

- Read `docs/design/README.md`, `docs/design/ui-brief.md`, `docs/design/token-contract.md`, and `docs/visual-documentation.md`.
- Keep repository design tokens as the checked runtime source.
- When the user supplies a Penpot link and MCP is available, inspect the focused design before planning.
- Start with read-only Penpot actions and record only real pages, boards, components, styles, and token names.
- Describe each Penpot write in the plan and wait for separate plan and implementation approvals.
- Make small reversible design changes, then reinspect the design and compare it with repository tokens.
- Do not claim a Penpot export, ID, or synchronization result without checked evidence.
- Keep one component hierarchy for desktop and mobile where practical.
- Cover keyboard use, focus, labels, contrast, reduced motion, and responsive overflow.
- Capture the implemented Nook Forge UI through deterministic Playwright automation.
- Never run an uploaded project merely to create screenshots for generated documentation.
- Keep personal uploads, live prompts, keys, file paths, machine names, and private trace content out of visual proof.

The design plan needs user approval before implementation. Design approval does not grant commit approval.
